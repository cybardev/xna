# 🧬 XNA 🛸

SpacetimeDB project scaffold with Nix

---

## Prerequisites

1. Click [<kbd>Use this template</kbd>](https://github.com/cybardev/xna/generate) here or the green button at the top-right corner.
2. Make your own repository from this template.
3. In your own repository, follow the remaining steps.
4. Clone your newly created repository locally.
5. If you have direnv, run `direnv allow` to automatically load the development environment when in the project directory.
6. Otherwise, you can run `nix-shell` or `nix develop` in the project directory to load it manually.
7. Next, `cd` into the `backend` subdirectory and follow the usage instructions in sequence.

## Usage

1. Open a terminal and run the backend:

```sh
spacetime start
```

2. Keep this terminal running, and open a new terminal window/tab and log in to the local server (only needed once):

```sh
spacetime login --server-issued-login local --no-browser
```

3. Publish the module to the local server:

```sh
spacetime publish xnadb --delete-data=always --yes
```

4. Start the log viewer:

```sh
spacetime logs xnadb -f
```

5. Keep this terminal running too, and open another one to call the reducers:

```sh
spacetime call say_hello
spacetime call add Kitty
spacetime call say_hello
```

6. The output from reducer calls show up in the terminal with the log viewer.

7. Now you're ready to develop a SpacetimeDB Rust module with Nix.

> [!NOTE]
> Once you close all the terminal processes running above, next time you want to return to it, skip running the `login` command. That only needs to be run the first time. And for the `publish` command, don't use the `--delete-data=always` flag if you want to preserve old data in the DB.

## FAQ

Q. Is this in any way related to the (long discontinued) [Microsoft XNA](https://en.wikipedia.org/wiki/Microsoft_XNA) Framework?  
A. No. The name is a mix of the word "DNA" and the handle of someone who inspires me.

Q. Why is this project archived? Is it no longer maintained?  
A. There's nothing to maintain. It works for the version of SpacetimeDB in the `nixpkgs` pinned in [flake.lock](./flake.lock) (spacetime 2.10.2).

Q. Why do you have an [AGENTS.md](./AGENTS.md) file? Are you a vibeslopper?  
A. No. I detest genAI (not the technology, but how it's being non-consensually enacted upon society). The file was generated by `spacetime init` and I found the documentation useful for myself. Kept the file as-is. I did delete all the other genAI redundancies they produced, such as ones for Cursor, GitHub Copilor, Claude, etc.
